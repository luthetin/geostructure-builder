# 多层面骨架编辑器

> 手工「捏」出任意地质界面：拖控制骨架 → 得到光滑曲面。
> 纯浏览器运行，零依赖，不联网。
>
> *A browser-based 3D editor for geological surfaces: sculpt a control skeleton, get a smooth surface. No dependencies, works offline.*

把 `index.html` 下载下来双击就能用。不需要安装任何东西，不需要服务器。

**在线版：https://luthetin.github.io/strata-skeleton/**（由 GitHub Pages 托管）

![界面](docs/screenshot.png)

*左：地层柱（4 个交界面夹出 3 个地层）　中：三维视图（地层是实体，四周切面实心，最下面接基底构成封闭块体）　右：实时平面图*

---

## 它在解决什么问题

研究地层界面（地层面、不整合面、断层面）时，常见做法是拿几何软件摆一个抛物面当地形、摆一个平面当地层，再求交线。这条路走得通，但很快会撞墙：

- **地形只能是最简单的形状。** 想换成真实山脊、沟谷、台地，就没有解析式可摆了。
- **界面也只能是平面。** 想加个褶皱、错个断层，参数化就崩了。

本工具换一个提法：**界面不是算出来的，是你捏出来的。**

用一张粗糙的**骨架面**（控制网格）去描述界面，程序用三次样条把它插值成光滑曲面。想把地形改成什么样，拖控制点就行 —— 山脊、沟谷、穹隆、鞍部，都能捏出来；骨架之间的拓扑关系天然支持任意复杂的形态。

而**地层是有厚度的实体**，不是没有厚度的面：两个交界面之间夹出来的那块形体就是地层，程序把它画成真正的实体（顶面 + 底面 + 四周侧壁），厚度看得见。

## 快速上手

| 操作 | 效果 |
|---|---|
| 拖控制点 | 改该点高度（作用于选中的交界面） |
| **Shift** + 点控制点 | 多选（再拖任一选中点即可整组升降） |
| **空格** + 上下拖 | 整个交界面升降（形不变） |
| 拖空白 / 右键拖 | 旋转视角 |
| 滚轮 | 缩放 |

左侧面板是**地层柱**：自上而下「新 → 老」，方块是地层（可改颜色/透明度/显隐），方块之间的横条是交界面（点圆钮选中它，也能改颜色/透明度）。右侧是实时平面图。

## 地质模型

```
ifaces[0..n-1]   交界面，自下而上排好序，各带一套骨架
strata[0..n-2]   strata[k] = ifaces[k] 与 ifaces[k+1] 之间的【形体】
```

**n 个交界面 ⇒ n−1 个地层** —— 两个交界面之间的层即为地层。

- 新建地层 = 在最上面加一个交界面（地表）+ 一个新的地层体
- 删除地层 = 去掉它的上交界面，让它与相邻地层并成一个
- 颜色与透明度挂在**地层体**上；交界面也有自己的颜色与透明度

## 功能

**骨架与曲面**
- 控制点排在平面整数格上，连成正方形、每格加一条对角线分成两个三角形 —— 就是骨架面
- 两种曲面：**插值型（Catmull-Rom）**曲面严格穿过每个控制点；**逼近型（三次 B 样条）**曲面被控制网拉着走
- 分辨率 5×5 ~ 13×13，切换时形状保留（在新控制点位置重采样旧曲面）
- 一键生成：谷地 / 丘陵 / 平拉 / 随机 / 平滑一次

**地层实体**
- 每个地层画成实体：顶面 + 底面 + 四周侧壁，绕序一律朝外
- 渲染分两趟（**所有**背面先画且不写深度，再画所有正面）—— 一个地层一个地层地画是不行的：后面地层的背面会先把深度写掉，把前面地层本该透出来的背面挡在门外，看上去就是"有的地层一半是透明的"
- 侧壁是"厚度看得见"的关键 —— 没有它，地层还是一片纸；而且侧壁永远是实心的（见下）

**沉积次序透明规则**

> 某处若有**更高的交界面压在下面**，该处这个交界面就透明；
> **夹着它的地层也跟着透明**，于是能直接看进内部 —— 相当于自动剖开一条地层剖面。

**完整规则是两半、一条约束、再加一条地层自身的存在判据。**缺哪一块都对应过一个具体的 bug：

```
S_i(x,y) = min over j>i of ( z_j − z_i )      ① 更年轻的界面压在它下面
         , min over j<i of ( z_i − z_j )      ② 更老的界面压在它上面

约束一：若界面 i 是该处【最高的】那个，S_i 强制为正（永不透明）
约束二：地层 k 的每一个面，都要再和【本层厚度】取 min：
        厚度 = ifaces[k+1] 的高程 − ifaces[k] 的高程，厚度为负 → 整层不画
S < 0  →  丢弃该片元
```

**①「更年轻的压在它下面」。** 这是最初写下的那条。

**②「更老的压在它上面」。** 看着多余（叠置正常时更老的本就都更低，一次都不触发），但它**是唯一能让最上面那个界面被判透明的途径** —— 它上面已经没有更年轻的界面了。少了它，上面那层尖灭（顶面扎到下面去）之后，**那个顶面还会照画不误，把下面那层一直挡着**：本该露出下面地层的颜色，显示的却还是上面地层的颜色。

**约束一「最高的那个永不透明」。** 这是②带来的新问题：地表扎下去以后，**被它扎穿的那个老界面反而成了该处最高的面**，也就是露出来的那个地表面。这时候①会在它身上触发（有个更年轻的界面在它下面），把它也丢掉 —— 于是那个位置**一个面都没有了**：本该露出下面地层的颜色，结果露出来的是"透明"。最高的那个界面是这一处的地表面，把它丢掉就没有面了。

**约束二「本层不存在就不画」。** 这是约束一带来的新问题，也是最隐蔽的一个：**一个交界面会被上下两个地层同时当作自己的边界** —— `iface 1` 既是地层0 的顶面、又是地层1 的底面，两者用的是同一个场。于是约束一把那个场抬成正数之后，**两个面一起画了出来**：上面那层明明已经尖灭，却靠自己的底面又出现在图里。所以地层的每个面都要再和本层厚度取 min：厚度为负（本层不存在）时整层消失；厚度为正的地方一个字都不改。

四条合起来的效果，正是想要的那张图：

| 位置 | 结果 |
|---|---|
| 叠置正常处 | 只有最上面那个面不透明，其余照旧 —— 行为完全不变（厚度处处为正，约束二不参与） |
| 地表扎穿中界面处 | 地表判透明（不再盖着）；**被剥露出来的那个面不透明**，看到它的颜色；**尖灭掉的那层整层消失**，不会靠底面冒回来 |
| 深扎到下界面以下 | 中界面也判透明，下界面（当下最高）露出来 |

**透明只从规则来，不从面板来。** 面板上调一个交界面的不透明度，只影响**那张面本身**；它上下两个地层的透明度各自独立，不会被带着变。想让地层透，调地层自己的滑块。只有上面这条**规则**才会自动透到地层上。这两件事必须分开：一个是"你没让我透"，一个是"地质上我本来就该透"，混在一起就没法手动控制了。

实现上这个规则不是逐顶点的 0/1 开关，而是一个**连续的有符号场**：

```
S_i(x,y) = 上面那两半取最小
S < 0  →  该片元被丢弃
```

在场上过零处丢弃片元，透明边界就**精确落在两面的交线上**。如果改用逐顶点开关，边界只能落在三角形顶点上，会呈网格状锯齿，正好把画在那条边界上的交线啃出缺口。

**侧壁（切面）用同一个场的连续版本，所以两端和顶/底面严格一致。**

顶面和底面是**面**，在每一点上判一次；侧壁是**一段高度**，要在**整段**上判。同一个规则沿高度展开就是一条直线：

```
f(z) = min over j>k of ( z_j ) − z          关于 z 的直线，斜率恒为 −1

下沿 z = z_k      →  f = bot.S          （和【底面】用的是同一个数）
上沿 z = z_{k+1}  →  f = min(0, top.S)  （和【顶面】同号）
f < 0 → 丢弃
```

三角面的两个顶点正好落在这两端，所以插值出来的就是这条直线本身。于是：

- **底面透明 ⇒ 侧壁下沿透明**，**顶面透明 ⇒ 侧壁上沿透明** —— 两端严格一致
- 两端同号（含恰好相切、尖灭）→ **整条实心**
- 只有一端为负 → 透明区是一条**楔形**，在相切处收拢到零，不会贯穿
- 两端都为负 → 整条贯穿

上沿那个 `min(0, ·)` 不是凑的：`f` 在两个端点上的真值就是 `bot.S` 和 `min(0, top.S)`，而 `min(0, ·)` 里那个 `0` 来自"这个界面到它自己的间距恰好是 0"。（曾经用一个"模型高程跨度"的自由尺度硬凑，那是错的，已经删掉。）

**基底（底平面 ↔ 第一个交界面之间那层）也走同一条直线**，不搞特殊。某个更高的界面压到 `ifaces[0]` 以下时，上面的地层会一直探进基底的深度范围，**两张切面共面重叠**，看上去就是一片竖条纹的 z-fighting（蓝色地层和基底的深棕色叠在一起）。基底的直线是：

```
f(z) = min over j>=1 of ( z_j ) − z

上沿（基底的顶 = 最低的那个交界面）→  f = bot.S
下沿（纯平地面高程）              →  f = C − 地面高程，C = 该柱最低的更高界面
```

`f` 在 `z = C` 处过零，也就是**C 以上的那截基底切面被丢掉** —— 正好是被上面地层占住的那一截。基底深度调大调小都不影响过零位置，因为过零位置由界面决定。

这个判据走过几个弯路，都记在这里免得再走回去：

| 写法 | 后果 |
|---|---|
| 侧壁完全不参与规则（基底也一直如此） | 规则在切面上彻底看不见；基底还会和上面的地层**共面重叠成竖条纹** |
| 侧壁改用"这一柱的厚度是否 < 0"判 | 判据和顶/底面**不同源** → 出现**俯视图透明、侧面却实心** |

**关键教训：侧壁的判据必须和顶/底面同源。** 一旦另立一个（不管是厚度、还是"永远实心"），就会出现"俯视图透了、侧面没透"这种不一致。

**基底与地面**
- 最下面自动长出一层**基底**：从最底下的交界面往下 `S.baseDepth`（默认 250 m），四周同样是实心侧壁
- 再加一个水平的地面/底面，于是整个模型是一个封闭的块体，像 Minecraft 的一个 chunk —— 转到底下看不会看穿
- 基底颜色、深度都可在面板上调

**交线与等高线**
- 交界面两两求交，交线画成贴在曲面上的连续红带
- **地表**（最上面的交界面）上的**构造等高线**（走向线），等高距可调，颜色/透明度可调
- 等高线数字按真正地形图的规矩：**线在数字处断开**、数字**沿线方向旋转**、**自动避让**不堆叠
- 平面图与 3D 视图共享同一套折线机制

**平面图（右侧）**
- 实时显示最高次序层面的等高线地形图，北在上
- 彩色（颜色表示高度）/ 黑白 / 层面自身色
- 可分别开关等高线与交线

**保存**
- 保存为 `.json`：含每个层面的骨架高程、颜色、透明度、次序、显隐，以及分辨率、曲面类型、视角、各类显示设置
- 导出 PNG（按画布真实分辨率，含高分屏）

## 地质背景

程序里的"等高线"不是随便画的等值线，是**构造等高线（走向线）**—— 线上每点高程都等于该条的标注高度，是判读产状、预测露头位置的基本工具。测试里对这一条做了逐点验证。

**高斯曲率**也能算并着色：红=穹隆（K>0）、蓝=鞍部（K<0）、灰=可展面（K≈0）—— 正是构造地质学里最要紧的三种形态。

需要注意：曲率是光滑曲面**本身**的属性，得先有光滑曲面才能算它，不能拿它来造曲面。造光滑曲面的算子是插值/逼近（本程序用样条）。所以这里的曲率是**分析显示**，不是生成手段。

## 技术说明

**不依赖任何库。** 渲染是手写的 WebGL（两个着色器程序、一个轨道相机、逐顶点属性），等值线是 marching squares，曲面是张量积三次样条。整个程序是一个 HTML 文件，不联网也能跑。

**交线几何为什么不按网格单元逐段生成。** 每格各做一条独立窄带的话，相邻段的"垂直方向"是各自算的，接缝处会错开 —— 每个错开就是一道缺口，连起来就是网格频率的锯齿。正确做法是先把线段**缝成折线**（网格边有唯一编号，交点天然共用），再沿折线生成**连续**窄带，每个顶点的垂直方向由前后邻点决定。测试里对此有专门断言。

**窄带必须骑在两张面之上。** 交线是两张面的交，窄带左右两侧分别落在两张面之上；只贴其中一张，另一半必然沉到另一张下面被深度测试切掉，看上去就是"带透明缺口的锯齿"。所以每个顶点取 `max(ZA, ZB)` 再抬高，且取样要和渲染网格用**完全相同的三角剖分**。

**地层的绕序必须对新。** 地层实体用两趟剔除渲染（先画背面再画正面），绕序写反就会把该看见的墙壁剔掉。顶面法线朝上、底面朝下、四周侧壁朝外，测试里逐个三角形算了几何法线来验证。

## 自动检验

```bash
node test/skeleton-check.js
```

用假 WebGL + 假 DOM 让程序在 Node 里完整跑起来，然后做数值断言。共 **148 项**，覆盖：

- **数学正确性**：Catmull-Rom 严格穿过控制点（误差 5.6e-8 m）；抛物面的高斯曲率与解析值 c² 相对误差 **0.000%**；穹隆/鞍部/圆柱面的曲率符号正确（圆柱面 K 精确为 0）
- **规则正确性（两半 + 两条约束）**：①"更年轻的压在它下面"逐点核对；②"更老的压在它上面"—— 这一半是唯一能让**最上面那个界面**被判透明的途径；约束一"当下最高的那个界面永不透明"逐点核对（7393+ 点全部保持不透明，扎下去的地表 7372 点全部判透明）；约束二"本层不存在就不画"逐点核对（面 = min(界面场, 本层厚度)，不符 0）。另断言：**叠置正常时②一次都不触发**、**被剥露出来的那层顶面 0/96 柱透明**、**没互穿的地方三个界面都不透明**（无误伤）\n- **共面双面**：一个交界面同时是上下两个地层的边界。断言尖灭掉的 23 个柱子里，上面那层的**顶面、底面、侧壁全都不画**（不会靠底面又冒出来），而**同一张面上下面那层的顶面仍然实心**（23/23）—— 这条专门抓「本该消失的地层又出现了」
- **侧壁与顶/底面【同源】**：3 个地层一起查，逐柱核对"底面透明 ⇔ 侧壁下沿透明"（160 柱）和"顶面透明 ⇔ 侧壁上沿透明"（128 柱），各不符 0。这条专门用来抓「俯视图透明、侧面却实心」这种不一致 —— 一旦有人给侧壁换个别的判据，它立刻会红
- **渐变与三种结局**：两端同号（含恰好相切、尖灭）的 98 柱全部实心；只有一端为负的 89 柱是楔形（不贯穿）；两端都为负的 101 柱才整条贯穿
- **透明只从规则来**：单独把交界面透明度调低，上下地层的透明度**一字不变**
- **基底也服从规则**：基底切面上"透明"与"z > 该柱最低的更高界面"逐顶点一致（不符 0/1152），被占住的那一截 429 个顶点全透、没被占住的 723 个全实心；基底上沿与它上方那个地层的底面同源（不符 0/96）；基底深度改成 900 m 结论不变\n- **实体几何**：地层的顶点数 = 顶面 + 底面 + 四壁；**侧壁法线逐个三角形验证朝外**；顶面法线朝上、底面朝上朝下；基底与地面构成封闭块体
- **几何正确性**：交线窄带中心线落在真交线上；每个顶点不低于两个界面；相邻四边形共用顶点（连续条带）
- **绘制正确性**：线段用 `LINES`、曲面用 `TRIANGLES`、手柄用 `POINTS`；地层**分两趟剔除**绘制，且是**全局**两趟（记录每次绘制时的实际 GL 状态与顺序）。数量对但模式错、或顺序错，都是一类抓不到的 bug，所以专门验状态
- **交互**：模拟鼠标键盘事件，验证多选、整组升降、空格整体升降、拖动灵敏度
- **存档**：保存→打开**逐字节一致**；拒绝格式错误、数据长度不符、地层数与界面数对不上的文件；**旧版存档能自动迁移**
